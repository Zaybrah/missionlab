# MissionLab: new feature ideas

Research report, 15 November 2026. Game version looked at: OPERATOR 0.09.5 (interop assemblies in `BepInEx/interop`).

**How to read this.** Everything under "what in OPERATOR could carry it" comes from the class listing only. A name proves that a type or member exists, not that it does what the name suggests. Nothing here was run in the game. "Remote call" means the listing also holds the matching `UserCode_…` method that Mirror generates for a Command, ClientRpc or TargetRpc; "SyncVar" means a matching `Network<Name>` property exists. Source keys such as [T5] point to the list in section 5.

---

## 1. Top picks

1. **Messages on every player's screen (idea 9).** Almost every other idea (objectives, timers, clues, Game Master narration) needs a way to tell unmodded friends what is going on. `ExfilZone.RPCHint(string, Popup.PopupType)` and `ExfilZone.TargetHint(conn, string, type)` are remote calls that carry free text, and every PvE mission has an `ExfilZone`. One call in a co-op session settles whether it works. If it does, it is the biggest single enabler found.
2. **Fair-play switch and lobby notice (idea 19).** The new Mod Policy (6 Nov 2026) allows gameplay mods in multiplayer "where everyone uses the same mods" and bans unfair advantage [O3]. A host-only mod sits in a gap in that wording. Marking modded missions with `OperationsManager.HasCheated` (a SyncVar that the achievement and leaderboard checks appear to read) and telling joiners that the lobby is modded costs little and removes the most likely complaint.
3. **Chance and either/or groups (idea 2).** A hand-made scenario that plays differently each time, with no new game call: the choice is made before the spawn list is built. DCS, Left 4 Dead and the game's own `ObjectiveSetter` all work this way [T7][T5].
4. **Mission check panel (idea 1).** The command-line check already exists; putting it in the editor with a list of problems (enemy on an island of the navmesh, trigger that can never fire, extraction that can never open) stops broken missions before a session is wasted. No game test needed.
5. **Respawn rules and rally points (idea 14).** In co-op a dead friend watches for the rest of the mission. `GameManagerNetwork.AllowRespawns` (SyncVar), `SERVER_SetRespawns(bool)`, `SERVER_RespawnALL()` and `InfiltrationManager.RPC_SetSpawnPosition(conn, pos, rot)` look like enough for "the team is brought back when it reaches a checkpoint".
6. **Enemy profiles (idea 12).** `BrainAI` and `WeaponsAI` expose skill, night vision, tactics, grenades and weapon choice per enemy. The enemy brain runs on the host, so there is nothing to sync and little to go wrong for friends. "Conscript", "bodyguard", "grenadier", "sentry with night vision" make scenarios read very differently.
7. **Mission type on any map (idea 11).** More missions is the request that comes up most on the Steam forum [O9][O12]. The game has `PVE_HVTKILL`, `PVE_FINDINTEL` and `PVE_ASSETDESTROY` as a synced mode, and "destroy the vehicle" fits the gun trucks MissionLab already places. Riskier than the picks above, but high value.
8. **Radio calls and the alarm as cues (idea 10).** The game's own pilot and drone voice lines and its alarm can be played for everyone from the host. That gives triggers a sound without shipping one.
9. **Trigger logic with "hold the zone" (idea 8).** AND/OR, counters, re-arming and "stay in the zone for N seconds" turn the existing triggers into defend and multi-stage missions. Pure logic in `MissionLab.Core`.
10. **Team status board and hand tools for the Game Master (ideas 22 and 23).** Health, bleeding and position of each player on the browser page, plus teleport, heal, resupply and freeze, are what Zeus add-ons added first [T3][T4].

**Test first, one co-op session, one call each:** `RPCHint` text; `HasCheated = true` and whether the end screen changes; `SERVER_RespawnALL()` after a death; `RPC_SetSpawnPosition` on a living player; `NetworkedCharacterVoicePlayer.Server_PlayExact` with a pilot line; `AlarmSystem.SetState(Alarm)`.

## 3. Game code finds

Systems in `Assembly-CSharp.dll` that MissionLab does not use yet. All from the listing; none tested.

**Text and sound that reach clients**
- `ExfilZone.RPCHint`, `TargetHint` (string + `Popup.PopupType` YellowWarning/RedWarning) → `HintManager.SpawnPopup`, `Popup.SetPopup`.
- `OperationUiSync` (SyncVars `CurrentLocation`, `OperationTime`, `InfilName`) feeding `OperationsUI.SetOperationName/Time/Infil`.
- `PlayerMaster.RPC_SendJoinMessage(string)`, `RaidManager.RPC_HVT_ConfirmKIA(string, int)`, `RPC_NotifyPlayerAIAmount(int)`.
- `NetworkedCharacterVoicePlayer` (`Server_PlayExact`, `Server_PlayRandom`, `Rpc_Play`), `VoiceCategory` with 39 pilot lines; `HelicopterV2.SERVER_SFX_*`, `HelicopterV3.ServerPlayComms`.
- `AlarmSystem` (`SetState`, `RpcUpdateAudioState`, SyncVars `syncedState`, `syncedAlarmClipIndex`).
- `WaveSurvival.SERVER_PlayRoundMusic(int, bool boss, float)`; `PvpGameode.RPC_PlayMusic`, `FFA.RPC_PlayMusic` (mode-specific).

**Lobby**
- Whiteboard: `PlayerDrawing.Server_DrawBrushStroke(BrushStroke)`, `RPC_DrawBrushStroke`, `Server_Clear()`, `RPC_ReceiveInitialTexture(conn, byte[])`. A host could draw a plan for everyone; the fields of `BrushStroke` are not shown by the listing tool.
- `LaptopProjector` (SyncVar `ProjectorActive`), `MissionLaptopNetworkState` (all lobby choices as SyncVars).
- Shoot house: `RangeComputer.RPC_UpdateLayout(layout, targets, civilians, hostageTakers)`, `shootHouseLayouts`, `RandomiseRange()`, SyncVars `targetsHit`, `civiliansHit`. A fixed "course of the week" looks possible. The only "civilians" and "hostage takers" in the game are these range targets.
- Host admin panel: `PlayMenu.admin_*`, `playerBoardItem.SERVER_KickPlayer`, `SERVER_BanPlayer`.

**Players**
- `GameManagerNetwork` SyncVars: `AllowRespawns`, `FreezeAllPlayers`, `FriendlyFire`, `DemiGM`, `ArmorySafety`, `EnableScoreBoard`; methods `SERVER_RespawnALL`, `SERVER_RemoveKitForAllPlayers`, `SERVER_FailOperation`.
- `InfiltrationManager.RPC_SetSpawnPosition` (TargetRpc), SyncVar `RaidTimer`.
- `PlayerNetworking.RPC_AddMagazines`, `RPC_PlayEmote`, `RPC_OpenMap`, `RPC_GetSuppressed`.
- `Health` (per-limb SyncVars, bleeding, fractures), `MedicalSystem`, `InventoryItem.ItemType` (medical items only).
- No revive or downed state for players, no spectator type beyond the free camera.

**Enemies**
- `BrainAI`: more than 70 plain settings (see idea 12), plus `GetFlashed(float, Vector3)`, `Evade()`, `FallBack`, `CautiousAdvance`, `TryProactiveFlank`, `teamConfidence`, `DoorInteractionMode`.
- `WeaponsAI`: weapon list and index, grenades, `SERVER_ThrowGrenade`, `CMD_DropWeapon`.
- `BotSpawnDetails`: `isSpawnGroup`, `GroupSpawnPoints`, `hvtLinkedSpawnGroup` (guards tied to the target's spot), `PatrolLooping`, `patrolWaitTime`, `DetectionTimeMultiplier`, `maxEffectiveRange`, `doorInteractionType`.
- Sound events for AI: `GameManager.ShotFired(pos, radius, shooterID, interior)`, `EyesAI.DoorSoundPlayed(pos, radius)`.
- `GameManager.SetAIDifficulty(AIDifficulty)` (Easy, Trained, Realistic, Tier1), `SetBotViewDistanceMultiplier(float)`.
- `V2AIParametres.Incapacitated*Clips`, `Health.ragdollBleedoutTime`: bots have a wounded state. No surrender, flee or morale member was found.
- A* Pathfinding: `Pathfinding.NavmeshCut`, `GraphUpdateObject`, `DynamicObstacle`, `NodeLink2` exist, so areas could be closed to enemies at run time (not turned into an idea; cost and stability unknown).

**World**
- `RaidManager.hasIEDs`, `IED`, `IED_locations`, `iedChance`, `iedCount`, `SERVER_SpawnIEDs()`: the game has its own roadside-bomb spawner. This is a lead for the parked "placed bombs" idea, the same way `SpawnStaticVehicleAI()` worked for gun trucks.
- `Destructible`, `SceneRandomiser`, `DynamicLight`, `SunSettings` (SyncVar `isNight`, `CMD_Switch`), `DoorV2` break/repair calls (idea 16).
- `ISR`, `Missile`, `SlapChargeExplosive`, `Landmine`, `ProximityExplosive` (phone bomb with ringtones).
- `VehicleAI.SERVER_SetCombatLights(bool)`, `VehicleHealth.missionObjective`.
- `Elevator`, `ElevatorButton` (plain MonoBehaviours, not networked), `PoliceLights`, `DamageZone` (damage over time in a volume, not networked).
- `ExfilZone.SpawnExfilVehicle()`, `linkedInfils`, `isHelicopter`.

**Host tools**
- Camera paths: `GameManager.FreeCamera_AddTrackPosition()`, `FreeCamera_PlayTrack(int)`; `ToggleHelmetCam()`, `ToggleBodyCam()`.
- A developer console (`QFSW.QC`), gated by `DevConsole.IsDeveloper` / `HasDevAccess`. Many `GameManager` methods look like its commands (`OpenAllDoors`, `ResetAllDoors`, `ToggleRespawns`, `ToggleExtractions`).

**Not found** (searched by name): hostages, civilians as characters, arrest or cuffs, surrender, smoke or gas grenades, keypads, security cameras, generators, player revive, chat, map pings, a mission editor.

**Limits of the local data.** The recon dumps supplied were written by Recon 0.1.0 to 0.2.2, so they hold no breakers, alarms or spawnable prefabs. Which maps contain an `AlarmSystem`, `ISR`, `Destructible`, `DynamicLight` or `WaveSurvival` object could not be checked. The lobby dump lists 11 PvE target packages and their modes: plain raid (Clean House, Darkwaters, Mexico Depot), target person (Georgia, Kabul Streets, Logar, Syria), find intel (Afghanistan, Violence of Action), destroy asset (Armenia), wave survival (Afghan Base).

## 4. OPERATOR community and roadmap

**What the developer has said**
- **Mod Policy, effective 6 November 2026** [O3][O5]. Mods are welcome when free for everyone at the same time, labelled unofficial, and not harmful to other players. Allowed gameplay changes are listed for single-player and for multiplayer sessions "where everyone uses the same mods". Banned: unfair multiplayer advantage, bypassing protections, redistributing the game or its full asset packages, names that start with "OPERATOR", official logos or key art. Suggested label: "An unofficial mod for OPERATOR. Not made or endorsed by Vector Interactive." The policy says nothing on host-only mods, reverse engineering, achievements or leaderboards.
- **What it means for MissionLab.** The name and the README label already fit. The host-only design is not covered by the wording, so: use it with friends who know, tell joiners, keep modded runs out of achievements and leaderboards (idea 19), keep `.mlgeo` and anything derived from game geometry local, and consider asking the studio (the policy gives a support address) whether host-only is acceptable.
- **Workshop support** was promised in October 2024 for "next year" and again in February 2026 as "probably" next year [O7]. No mission editor, hostages or civilians have been announced [O4][O5]. The policy mentions a possible future paid "creator program" [O3].

**V10** [O2][O4][O5]
- Announced contents: new character model and first-person animations, new clothing, drag-and-drop gear and weapon customisation, a UI rework, two maps (Ukraine Streets, a Darién Gap jungle). The official page calls it a "major rework". The July devlog gave "3–6 months", so it is due about now; the 5 November post says more details soon.
- Nothing in it duplicates MissionLab.
- What it can break: every interop name after a rebuild; the lobby code MissionLab hooks (`OperationBoardUI`, `MissionLaptopNetworkState`, `InfilSelectorDisplayer`) because of the UI rework; anything touching the player object. The 0.09.5 listing already holds the switch (`GameManager.useNewCharacter`, `PlayerMaster.PlayerV1Prefab` / `PlayerV2Prefab`, `CharacterCustomisationV2`). New maps need new navmesh matches and recon runs. Advice: keep game calls behind one thin layer, re-run Recon on day one, and hold back features that depend on player internals (ideas 14, 15, 23) until V10 is out.
- V09.5 (July 2026) already added a setting for the number of target persons and random target spawns in simulations, and fixed wave-survival AI [O4]. Check ideas 11 and 17 against that before building.

**What players ask for that a host-side mod could deliver**
- More missions and variety; one reply asks for a Game Master and scenario builder like Arma Reforger's [O9]. Another thread asks for replay value through enemy choice, more objectives and more than 60 enemies [O12]. This is MissionLab's core; ideas 2, 11, 28 and 29 answer it most directly.
- Hostages and unarmed civilians [O8]. Only a stand-in is possible (idea 20).
- Target-person missions: players cannot find or confirm the target, or extraction does not open [O10][O11]. A scenario with a clear clue (ideas 9, 30) and its own extraction rule would help.
- A 2024 developer reply admitted that the only objective was killing [O13]; reviews still call the game "content-light" [O17].
- No developer reply was found in the request threads read. Some threads showed only part of their comments.

**Other mods (new since MissionLab's docs were written)**
- **Modded Operations Framework** [O14]: BepInEx 6 IL2CPP be.785 (the same loader), adds a "MODDED OPS" section to the mission laptop, loads custom maps from asset bundles, has per-map AI profiles. Every player needs identical files. Its page claims the lead developer supports community modding (not verified). A map built on it exists [O15], and the page names an "Operator Mod API Core".
- **Archduke Interactive** [O16]: a pack of 38 mods with a 15-mission campaign, changed enemy behaviour, a friendly squad, parachute and helicopter insertion; installed by its own launcher; renamed because of the policy's naming rule.
- **What it means.** Nobody else found offers host-only play with unmodded friends, a browser editor or a live Game Master; that is MissionLab's niche. Two plugins on the same loader hooking `RaidManager` and the laptop can collide, so a compatibility check is worth doing. Supporting community maps (reading the live `RecastGraph` when no shipped navmesh file matches) would widen the audience; there everyone is modded anyway.
